v0.25에서는 출전하자마자 나던 배경 소리를 뺐다. 관중 웅성거림의 반복과 배경 선율이 없어져, 아무 동작도 없을 때에는 조용하다. 토스·타구·바운드 소리, 득점음·폴트음, 특수기술 효과음, 관중의 박수·환호·항의는 그대로다. 규칙·능력치·기술·저장 형식은 v0.24와 같다.

v0.24에서는 ‘데스크톱 권장’ 안내 상자의 테두리를 눈에 덜 띄게 고쳤다. 색은 노란빛이 도는 연한 빨강(살구색)이고, 페이지를 열면 처음 열 번만 깜빡인 뒤 켜진 채 머문다. 탭을 오가도 다시 깜빡이지 않는다. 주소 끝에 `?motion=reduce`를 붙이면 처음부터 깜빡이지 않는다. 문구·규칙·능력치·기술·저장 형식은 v0.23과 같다.

바로 앞 판 v0.24의 [v0.24 릴리스](https://github.com/Raspberry-Kim/donghyun-lab18/releases/tag/v0.24)·[Zenodo 보관본](https://zenodo.org/records/24328441)은 DOI `10.5281/zenodo.24328441`이며, ZIP의 모든 파일을 v0.24 태그와 대조해 차이 없음을 확인했다. DOI와 공개 검사 결과는 태그 발행 뒤 문서에 기록했으며, 태그와 보관본 자체는 옮기거나 바꾸지 않았다.

v0.23에서는 코트 위 ‘데스크톱 권장’ 안내 상자의 테두리를 빨간색 점멸로 바꿨다. 옅은 점선 1px이던 테두리가 빨간 실선 2px가 되어 1초에 한 번 깜빡인다(켜짐 0.5초·꺼짐 0.5초). 상자 크기와 아래 배치는 그대로다. 기기의 동작 줄이기 설정과 무관하게 깜빡이며, 주소 끝에 `?motion=reduce`를 붙이면 깜빡이지 않는 빨간 테두리로 보인다. 문구·규칙·능력치·기술·저장 형식은 v0.22와 같다.

v0.22에서는 두 가지를 고쳤다. 맥에서 `⌘+Enter`를 눌러도 출전이 되지 않던 오류를 고쳐, `Ctrl+Enter`와 같게 동작한다. 화면의 안내에는 처음부터 두 키가 함께 적혀 있었다. 휴대폰을 가로로 눕힌 전체 화면에서는 코트를 왼쪽에 세로 가득 두고 점수판·상태·기술 줄을 오른쪽에 쌓는다. 734×343 화면에서 코트가 178×169에서 348×331로 커진다. 세로 화면과 데스크톱의 전체 화면은 그대로다. 규칙·능력치·기술·저장 형식은 v0.21과 같다. 터치 조작판은 여전히 없으며 조작은 키보드와 게임패드로 한다.

v0.21에서는 윈도우 크롬·엣지에서 특수기술의 동작이 멈춘 그림으로 나오던 오류를 고쳤다. 윈도우 설정에서 ‘애니메이션 효과’를 꺼 둔 PC는 브라우저에 동작 줄이기를 알리는데, 그동안 게임이 이 설정을 따라 기술 그림의 시각을 멈춰 두었다. 이제 코트 그림은 운영체제 설정과 관계없이 같은 동작으로 그린다. 규칙·능력치·기술의 효과·저장 형식은 v0.20과 같다.

v0.20에서는 또치의 머리를 앞에서도 뒤에서도 동그랗게 그렸다. 가로가 좁아 보이던 11×12 그림을 13×12로 넓혀, 화면에서 가로·세로가 거의 같다. 포동이는 모든 선수 가운데 가장 작게 줄였다. 머리는 15×11에서 11×8 그림으로 가로·세로 약 27% 작아졌고, 몸·팔·라켓은 0.82배(18% 작게)로 그린다. 머리는 제 크기 픽셀로 그려 눈·코·귀가 흐려지지 않는다. 키는 20칸으로 슈슈(22칸)보다 작다. 그림만 바뀌었으며, 타격 범위·능력치·기술·저장 형식은 v0.19와 같다.

v0.19에서는 커트코베인 설명을 ‘결국 뭉치가 포인트를 얻는다’로 고치고, 관중 소리 설명에서 지금은 없는 ‘게임을 내주는’ 동작을 뺐다. 기술의 동작·비용·점수 규칙은 v0.18과 같다.

v0.18에서는 뭉치의 S를 새 액슬로즈, A를 커트코베인으로 바꿨다. 액슬로즈는 제자리 뱀춤과 자동 구석 리턴, 커트코베인은 긴 라켓 파손과 상대 도주 뒤 한 포인트 획득이다. 다른 선수·코트·일반 타격 규칙은 그대로다.

v0.16에서는 설명 글을 다듬었다. ‘단추’는 ‘버튼’으로 쓰고, ‘수학적 원리’ 머리말과 ‘모델과 출처’에서 평가하는 꾸밈말을 덜어 냈다. 규칙과 판정은 그대로다.

v0.15에서는 ‘수학적 원리’의 말을 다듬었다. 화면 투영 절은 코트 좌표가 화면 어디에 어떤 크기로 놓이는지 풀어 썼고, 특수기술이 언제 꺼지고 언제 남는지도 특수기술 말로 다시 적었다. 식과 규칙은 그대로다.

v0.14에서는 동현이 남색 야구모자를 거꾸로 썼다. 앞에서는 이마 위 조임 띠 구멍으로 흰머리가 살짝 보이고, 뒤에서는 챙이 목 쪽으로 나온다. 샤아자쿠의 발동 표지와 코트 테두리, 공 쪽으로 달려가는 궤적은 하늘색에서 붉은 계열로 바뀌었다.

v0.13에서는 선수 둘이 더 왔다. **이삐**는 꽥꽥만 한 키의 단발 어린 소녀로, 얼굴은 슈슈를 닮았다(공격 70 · 수비 90 · 이동 100). S **양재천범람**을 켜면 내가 친 공과 함께 물결이 네트를 넘어 상대를 덮치고, 젖은 상대의 이동은 90% 느려진다. A **브롬톤앞바퀴**는 닿지 않는 공에 타격 키를 누르면 앞바퀴를 타고 0.2초 동안 굴러가 친다. 동현의 샤아자쿠보다 조금 느리고, 다섯 번에 한 번꼴로 공 옆으로 미끄러져 놓친다. **빽빽**은 슈슈와 거의 같은 모습에 똥머리와 연보라 원피스만 다르다(공격 90 · 수비 100 · 이동 110). S **오마이갓**을 켜면 내가 친 공이 하트 다섯 갈래로 갈라지는데 진짜는 무작위 하나다. 상대가 우연히 진짜를 고르면 랠리가 이어진다. A **백미취사완료**를 켜면 내가 공을 칠 때부터 상대가 취한 듯 비틀거리며 네트 쪽으로 걸어온다. 선수는 아홉, 기술은 열여덟, 예제는 81개가 됐다.

v0.12에서는 ‘수학적 원리’를 처음부터 다시 맞춰 봤다. 스매시의 수평 속도 배수를 바운드 뒤(×0.74)와 바운드 전(×0.80×0.74≈0.59)으로 나눠 바로 적었고, 긴 식은 좁은 화면에서 잘리지 않고 그 자리에서 줄이 바뀐다. 경기 규칙과 조작은 그대로다.

v0.11에서는 포동이 얼굴을 시리즈 머리글 아이콘처럼 둥글게 다듬고 귀를 흰색으로 맞췄다. 까만 눈과 코, 작은 입을 넣었고 키는 꽥꽥만큼 작다. 몸과 동작은 그대로이며, 쓰러진 자세의 머리에 생기던 줄무늬도 고쳤다.

득점에는 박수, 긴 랠리와 스매시에는 환호가 이어진다. 라켓이 부러지면 항의성 소음도 들린다. 아무 동작도 없을 때에는 조용하다. 모두 녹음 없이 합성한 소리다. 머리글 소리 버튼이나 M으로 함께 끌 수 있고, 메뉴를 열거나 다른 탭으로 이동하면 관객 소리도 멈춘다.

v0.10에서는 상대가 경기마다 바뀐다. 내 선수를 뺀 여섯 명 가운데 무작위로 정해지므로 같은 선수끼리는 만나지 않는다. 동현의 뒤통수는 검은 점을 줄인 부드러운 회색으로 바꿨다. 화면을 두 배 해상도로 그려 슈슈를 동현파 원본 도트 그대로(1:1) 보여 주고, 다른 여섯 선수는 크기와 모양을 그대로 둔 채 도트 사이 틈만 없앴다.

v0.09에서 내 선수는 출전 전 시작 카드에서만 앞 얼굴을 보이고, 출전한 뒤에는 뒤통수를 보인다. 상대 선수는 계속 앞을 본다. 동현은 머리 위 꽁지머리를 없애고 흰머리와 검은머리가 섞인 색으로 바꿨다.

v0.08은 머리 중심의 둥근 캐릭터를 그렸다. 동현은 흰 머리 남성, 뭉치와 꽥꽥은 단발 여성(꽥꽥은 조금 작은 키), 뚱띠는 넓고 건장한 인상, 또치는 귀엽고 가느다란 인상이다. 포동이의 흰 귀·주둥이를 키웠고 슈슈의 원본 디자인·몸체·팔다리·라켓과 고정 코트는 보존했다. 상대 슈슈는 대기와 후진에서도 앞을 본다.

## 시작과 조작

데스크톱을 권장한다. 경기에서는 키보드와 표준 매핑 게임패드를 사용하고, 마우스·터치 이동이나 타격은 제공하지 않는다. 휴대폰에서 경기하려면 별도의 키보드를 연결하자.

| 키 | 동작 |
|---|---|
| 방향키 | 이동, 타격 방향·깊이 |
| X | 토스, 강한 서브, 스트로크 |
| Z | 약한 서브, 로브·약한 발리 |
| S / A | 첫째 / 둘째 기술 |
| Enter | 출전, 메뉴(계속 · 저장 · 불러오기 · 포기) |
| F / Esc | 전체 화면 / 닫기 |
| M | 소리 전환 |
| Ctrl+Enter · ⌘+Enter | 코드로 새 경기 시작, 진행 중이면 확인 |

메뉴에서는 ↑↓로 고르고 Enter·X로 선택, Z·Esc로 뒤로 간다. 게임패드는 십자키·왼 스틱 위아래, 오른쪽 버튼·Start 선택, 아래 버튼 뒤로다.

GB A는 X, GB B는 Z다. X는 가로로 미는 스트로크, Z는 아래에서 위로 띄우는 로브로 자세·궤적을 구별한다. 라켓 타원의 긴 축은 손잡이와 이어지고, 회전 중 면 너비도 달라진다.

서브는 좌우 출발 위치를 고르고 X로 토스한 뒤 X/Z로 친다. 높은 공 입력은 준비해 두었다가 닿는 높이에서 친다. 출발 위치·타점 높이·타격 직후 0.12초의 방향 입력이 함께 착지를 결정한다. 짧게/길게 누르는 시간과 스틱 크기를 반영하되 그 뒤 공 조향은 없다. 이 입력 구간은 원작 수치의 복제가 아니라 동현테의 여유 설정이다. 공은 높이에 따라 커지고 토스에는 ‘부웅’ 상승음이 난다.

코트 교대의 경기 좌표는 유지하되 화면 좌표를 변환해 내 선수는 항상 하단에 둔다. 카메라는 움직이지 않고 방향키는 화면 기준으로 작동한다.

코드는 선수 1–9, 난이도 1–3, 경기장 1–4를 차례로 출력한다. 선수 번호는 동현·뭉치·뚱띠·또치·포동이·꽥꽥·슈슈·이삐·빽빽 순이다. 예제는 통상 36개 → 프로 36개 → 초보 9개 순서이고, 묶음 안에서는 선수 순, 같은 선수면 코트 순이다. 통상·프로에서는 아홉 선수 모두 네 코트를 선택하며 초보 예제는 모두 윔블던이다. 01·37·73으로 동현·윔블던의 난이도를 비교하고, 각 선수의 통상·프로 예제 네 개로 코트를 비교하자. 선수 카드의 ‘코드 불러오기’는 그 선수의 초보·윔블던 예제를 연다. 직접 코드를 쓰면 초보의 다른 코트도 선택할 수 있다.

## 저장과 불러오기

경기 중 Enter 메뉴의 ‘저장’에서 브라우저 칸 1–3이나 `.dhsave` 파일에 지금 경기를 담는다. 점수·서브 순서·에너지, 날아가던 공, 준비한 기술, 난수 상태까지 들어 있어 불러오면 같은 입력에 같은 결과가 이어진다. 불러오기는 메뉴와 코트 탭 B 칸 아래에 있고, 불러온 경기는 멈춘 채로 열린다. 출전 코드 칸도 불러온 경기의 설정으로 바뀐다.

브라우저 칸은 그 기기의 그 브라우저에만 남는다. 사이트 데이터를 지우면 사라지므로 오래 둘 경기는 파일로 내려받자. 끝난 경기는 저장하지 않는다. 저장 형식이 아니거나 값이 범위를 벗어난 파일은 이유를 알리고 거절하며, 하던 경기는 그대로 둔다. 저장 파일의 글자는 화면에 글자로만 표시한다.

## 구현

특수기술이 받아들여지면 코트 상단에 선수·기술명과 준비/발동 상태가 약 1.6초 나타나고, 코트 가장자리에 기술 색 테두리가 두 번 맥동한다. 불꽃·혜성·시계·음표·발바닥·하트·표적 등 작은 상징과 입자가 효과를 알린다. 다음 타격을 기다리는 기술은 먼저 ‘준비’, 실제 사용 때 ‘발동’으로 구별한다. 실패한 입력에는 성공 연출이 없고 기존 상태 줄에 이유가 나온다. 카메라는 흔들리지 않으며 화면 전체를 덮는 섬광도 없다. 메뉴를 열면 연출도 멈춘다. 기술의 동작은 기기의 동작 줄이기 설정과 관계없이 같게 그린다. 동작을 줄여 보려면 주소 끝에 `?motion=reduce`를 붙이며, 이때는 상징과 표지만 정적으로 표시한다.

기술이 걸려 있는 동안에는 코트에도 표시가 남는다. 준비한 기술은 발밑 고리, 울트라롱팔은 남은 횟수 점과 공까지 뻗는 팔, 리만가설은 예상 궤적과 십자 표식, 와루이지와나는 공 둘레 시계 고리, 컴온스펜서는 음표, 아잉뿌잉은 하트와 남은 시간 칸이다. 양재천범람은 공을 따라가는 물마루와 물에 잠긴 상대 코트, 브롬톤앞바퀴는 발밑 바퀴와 굴러간 자국, 오마이갓은 나란히 날아가는 하트 다섯 개(그림자는 진짜 공에만 있다), 백미취사완료는 상대 머리 위를 도는 고리와 비틀거리는 걸음이다. 불꽃·바람·드롭·사라지는 공은 공 자체에 꼬리와 깜박임이 붙는다. 코트 아래 기술 칸에는 ‘준비됨 · 다음 리턴’, ‘발동 중 · 남은 2번’처럼 상태가 적히고, 풀릴 때는 안내 줄에 알린다.

뭉치의 **액슬로즈(S)**는 라켓을 머리 위에 들고 상체·골반을 반대로 흔드는 제자리 뱀춤이다. 상대 공이 네트를 넘으면 이동·타격 입력 없이 자동으로 구석에 리턴한다. 상대가 다시 넘기면 그 위치에 따라 다음 구석을 다시 고른다. 내 서브도 자동으로 넣고, 상대 서브는 유효한 첫 바운드를 확인한 뒤 받는다. 상대 실수로 내 포인트가 될 때까지 계속하며, 폴트·렛·내 실수 뒤에도 효과는 남는다.

구석은 좌우 ±3.895 m와 상대 코트의 앞 1.7 m·뒤 11.585 m를 조합한 네 곳이다. 상대의 이동거리에서 닿는 거리를 빼고 이동속력으로 나눈 뒤 공의 비행시간을 뺀 값이 가장 큰 곳을 고른다. 실제 최적 전술을 보장하는 계산은 아니며 받기 어려움을 정한 게임용 기준이다. 공격력 90과 기존 강한 발리·스매시 시간 배수 0.80 × 0.74를 사용하고, 비행시간 하한은 0.5초/난이도 속도다. 낮은 공은 네트 위 0.10 m를 통과하는 데 필요한 만큼만 시간을 늘린다. 상대는 보통 이동·타격 판정으로 받을 수 있고, 첫 바운드만으로 강제 득점하지 않는다.

**커트코베인(A)**은 8.4초 동안 라켓을 열두 번 내리쳐 부순다. 상대는 라켓을 버리고 겁먹은 얼굴로 사방으로 방향을 바꿔 뛰며, 공이나 경기 전술을 따라가지 않는다. 연출 중에는 점수가 바뀌지 않고, 끝나면 결국 뭉치가 한 포인트를 얻는다. 타이브레이크도 한 포인트이며, 그 득점이 게임·세트·경기를 끝내면 평소 득점 규칙을 따른다. 연출 도중의 재사용은 막으며 일시정지·저장·불러오기가 된다.

예제 제목은 모두 ‘번호 · 선수 · 난이도 · 코트’ 순서다. 예제 선택 칸 아래 설명에서 속도 배율, 상대 재판단 간격과 바운드 전 좌우 목표 오차, 수직 반발과 수평 속도 유지율을 확인하자. 수직 반발 계수는 바운드 직후 속도의 비율이지 높이의 비율은 아니다. 이 수치는 원작에서 추출한 값이 아닌 동현테의 자체 설정이다.

- **선수**: 동현·뭉치·뚱띠·또치·포동이·꽥꽥·슈슈·이삐·빽빽, 선수별 능력치와 18개 기술.
- **경기장**: 윔블던·호주·US·프랑스. 색상·반발·바운드 뒤 속도 유지율을 구분.
- **기술 에너지**: 시작·최대 6칸, 일반 기술 1칸·액슬로즈 3칸. 포인트 종료마다 +2, 성공한 리턴 2회마다 +1. 두 기술 동시 준비, 중복 입력 무과금. 포인트 사이에도 지속형/필승형을 미리 준비할 수 있다.
- **기술 수명**: 샤아자쿠·사세보후우샤·와루이지와나·컴온스펜서·멍멍·아잉뿌잉·울트라롱팔·리만가설·양재천범람·브롬톤앞바퀴·오마이갓·백미취사완료는 랠리 종료까지 유지한다. 이삐·빽빽의 네 기술은 서브도 타격으로 세고, 폴트·렛에서는 그대로 남는다. 샤아아즈나블·구마몬기쥬츠·비밀이야·알려고하지마는 유효한 착지로 성공해야 소모된다. 아웃·더블 폴트·사용 못 한 포인트 뒤에도 다음 랠리로 이월한다. 액슬로즈는 내 득점까지 자동 리턴을 이어 가며, 커트코베인은 연출 뒤 한 포인트를 준다. 상대 동현AI™는 기술을 쓰지 않는다.
- **저장 호환**: 이전 v1 저장도 읽는다. 이전 횟수·초 단위의 긴 팔·쓰러짐과 준비된 혜성/바람 효과는 불러올 때 새 랠리 지속 규칙으로 바꾼다. 파일의 점수·코트·난수·공 좌표는 보존한다. v0.18의 뱀춤·도주 상태도 저장한다. 옛 액슬로즈 파손 연출 도중의 저장은 이미 기록된 점수를 바꾸지 않고 남은 옛 연출만 마친다.
- **기본 경기**: XYZ 포물선, 그림자, 높이·거리·타이밍 타격, 서브 폴트·렛, 네트·인·아웃·두 번 바운드, 듀스·어드밴티지·타이브레이크·2세트 선승.
- **화면**: 고정 시점, 단순한 절차적 도트, 앞·뒷모습, 잔 다르크 심판, 밝은/어두운 UI.
- **상대**: 내 선수를 뺀 여덟 명 가운데 경기마다 무작위. 같은 선수끼리는 만나지 않는다. 슈슈는 동현파 원본의 양쪽 둥근 머리·리본·분홍 원피스·빨간 운동화 도트를 1:1로 쓴다. 동현AI™는 일반 타격만 사용한다.

## 원작과의 관계

1989 GB 테니스를 실행하여 코트·선수 크기·토스·공과 그림자를 관찰했다. 기계어를 역분석한 것이 아니며, 물리 상수와 타격 판정이 원작과 수치적으로 일치하지 않는다. 이 구현을 정확한 복제라고 부르지 않는다.

두 단계 서브, A 스트로크·강한 발리, B 로브·약한 발리, 높은 공의 스매시와 방향 조절은 [Nintendo Tennis 설명서](https://www.thegameisafootarcade.com/wp-content/uploads/2017/04/Tennis-Game-Manual.pdf)를 참고했다. 원작에서 관찰한 화면 이동은 재현하지 않았다. 동현테는 고정 시점으로 진행한다.

네 코트의 계수는 자체 조절값이다. 실제 대회 측정치나 롬에서 추출한 상수가 아니며, 세 난이도와 특수기술도 동현테의 추가 규칙이다.

## 개발

```sh
node qa/core.cjs
node qa/skill-rules.cjs
node qa/rally-skills.cjs
node qa/skill-cues.cjs
node qa/motion.cjs
node qa/round.cjs
node qa/serve-timing.cjs
node qa/racket-input.cjs
node qa/new-skills.cjs
node qa/mungchi.cjs
node qa/bot.cjs
node build.cjs
# 브라우저 검사: dist를 3018번 포트로 띄운 뒤
node qa/examples-ui.mjs
node qa/save-ui.mjs
node qa/pad-menu.mjs
node qa/layout-ui.mjs
node qa/mungchi-ui.mjs http://127.0.0.1:3118/
node qa/windows-motion.mjs http://127.0.0.1:3118/
node qa/run-key-ui.mjs http://127.0.0.1:3118/
node qa/note-blink.cjs chromium http://127.0.0.1:3118/
```

`src/engine.js`는 화면과 독립적인 120 Hz 엔진이다. `render.js`는 도트·코트, `app.js`는 동현랭·입력·메뉴·소리를 담당한다. `build.cjs`는 원본 실행기와 글꼴을 포함한 단일 HTML을 `dist`에 만든다.

웹 배포 대상은 `dist`다. 롬·에뮬레이터 상태·원작 캡처·비공개 분석 자료는 저장소·릴리스·Zenodo 보관본에 포함하지 않는다.
